# Roll20 comparison baseline — 2026-09-05

This is an independent, read-only review of official Roll20 documentation and release posts accessed on September 5, 2026. It establishes the current competitor baseline for Open Tabletop Engine (OTE), not a verdict that either product is better. No Roll20 account, purchase, private campaign, user interview, or timed comparative playtest was used. Product claims below mean documented capabilities, not independently observed usability, reliability, or market preference.

## The bar has moved

Do not compare OTE to a memory of legacy Roll20. The current engine launched out of beta in January 2025. During 2026, Roll20 added native UVTT map ingestion, a true Player View, broader map pins, secret rolls, mobile character workflows, and guided grid alignment. These are meaningful workflow improvements rather than merely a renderer replacement. [Jumpgate launch, January 6, 2025](https://blog.roll20.net/posts/the-future-of-tabletop-gaming-jumpgate-officially-launches/).

The authoritative change log was updated September 2, 2026: Mod Script Sandbox 1.5 became the default unless a version was explicitly chosen; 1.0 remains selectable. The grid-alignment beta announced August 19 was temporarily rolled back, then relaunched August 26. September 1 changes include more aura shapes/borders and fixes for token synchronization, lighting, and Jukebox issues. A historical bug report is not evidence that the current product still exhibits it. [Current Change Log, September 2, 2026](https://help.roll20.net/hc/en-us/articles/360037772613-Change-Log).

## Documented workflow baseline

| Area | Current documented capability and constraint | Why it matters for an honest comparison |
| --- | --- | --- |
| Onboarding | Create a game, select a sheet or prepared module, invite players, and launch. Free adventure tutorials cover building through running a session. New D&D ready-to-play characters include leveling choices and work in the VTT and Roll20 Characters. [Crash Course, September 2023](https://help.roll20.net/hc/en-us/articles/360039223834-Roll20-Crash-Course); [Ready-to-Play Characters, May 29, 2026](https://blog.roll20.net/posts/new-dd-characters-ready-to-play-instantly/) | A successful signup and an empty canvas do not establish parity with reaching the first playable encounter. |
| Map preparation | Native `.uvtt`, `.dd2vtt`, and `.df2vtt` uploads create a page with background, walls, portals, and light sources. Everyone can upload; free accounts see the static map, while Dynamic Lighting use requires a subscription. Dungeon Scrawl maps can update the VTT as they are drawn, including a connected random-dungeon option. [Page Menu and UVTT release, July 16, 2026](https://blog.roll20.net/posts/page-menu-updates/) | UVTT import and procedural map generation are already competitor features. Test the full path to playable lighting, including source-specific portal corrections. |
| Grid and scene setup | The guided alignment beta uses anchor, scale, and fine tuning. A Map Layer hotbar exposes upload, grid types, offset, dimensions, units, and backdrops. The beta is free for GMs and was relaunched August 26. [Alignment release, August 19, 2026](https://blog.roll20.net/posts/align-to-grid-new/); [Current Change Log](https://help.roll20.net/hc/en-us/articles/360037772613-Change-Log) | OTE must make arbitrary user maps practical, including borders, offsets, scale mistakes, and non-square grids. |
| Lighting and doors | Dynamic Lighting includes player vision, nightvision/nocturnal vision, explored areas, and permanent darkness. Doors can be secret, locked, and opened; windows permit sight and can allow movement. Doors/windows support copy, paste, and bulk operations; correct page/token setup and movement restriction matter. [Player lighting guide](https://help.roll20.net/hc/en-us/articles/11786989363479-Using-Dynamic-Lighting-As-A-Player); [Doors and Windows, October 27, 2025](https://help.roll20.net/hc/en-us/articles/11462645998999-Placing-Doors-Windows) | One attractive fog screenshot does not demonstrate a usable lighting workflow or visibility correctness. |
| GM rehearsal and support | Player View opens a named player's view in another tab, including permission-dependent Journal, Chat, and map state. GMs can configure macros and act on the player's behalf. GM chat actions are attributed, player-to-player whispers remain private, and device-local voice/video settings are not reproduced. [Player View release, July 15, 2026](https://blog.roll20.net/posts/player-view-is-here/) | A token-vision preview alone is a smaller capability. Full player rehearsal must cover permissions, handouts, chat, and controls. |
| Live tabletop | Turn tracker, shared/private measurement, movement measurement, waypoints, card decks, rollable tables, custom markers, text chat, music, and macros are established tools. [Crash Course](https://help.roll20.net/hc/en-us/articles/360039223834-Roll20-Crash-Course); [Measure Tool, April 29, 2026](https://help.roll20.net/hc/en-us/articles/360039674913-Measure-Tool) | Judge interruptions and actions required during a complete encounter, including GM improvisation. |
| Interactive scenes | Subscriber foreground layers support overhead art and conditional fading. Send-to-Chat Reactions can trigger text, rolls, macros, and Mod Scripts on overlap, with one-shot/manual-reset or repeating behavior. That release states a GM must be present for player-triggered Send-to-Chat reactions. [Foreground release, June 17, 2025](https://blog.roll20.net/posts/foreground-out-of-beta/); [Send-to-Chat Reactions, November 25, 2025](https://blog.roll20.net/posts/send-to-chat-reactions/) | Automatic traps and environmental interactions are not unique OTE advantages. Compare authoring, debugging, and actual trigger behavior. |
| Rules and compendium | Sheet-specific compendium integration can turn a dropped monster into a populated NPC sheet, and populate equipment/spells on supported character sheets. Free reference content and licensed expansions have different coverage; integration depends on the sheet. [Compendium, September 5, 2023](https://help.roll20.net/hc/en-us/articles/360039178694-Compendium) | A generic actor schema and a few rules fixtures do not match mature, connected character workflows or licensed rules breadth. |
| Ready-made content | The March 2026 Curse of Strahd remaster combines room-linked map pins, overhead art, automatic traps, two D&D sheet variants, and a mobile-friendly Demiplane reader. It is a new add-on rather than an automatic patch to existing campaigns. [Remaster release, March 25, 2026](https://blog.roll20.net/posts/curse-of-strahd-is-remastered-on-roll20-major-improvements-inside/) | This is a hard end-to-end benchmark: open a professionally prepared adventure, find the room, run its encounter, and adapt it. |
| Communications | Browser WebRTC voice/video includes selectable devices, reconnect tools, and GM multi-player voice whispers. Roll20 also has a Discord Activity, using Discord communication rather than duplicating VTT voice/video inside it. [Integrated Voice and Video](https://help.roll20.net/hc/en-us/articles/360041544734-Integrated-Voice-and-Video); [Discord Activity](https://help.roll20.net/hc/en-us/articles/25838862126359-Roll20-Discord-Activity) | One working chat channel does not prove communication parity, and server-local media tests do not prove real network quality. |
| Mobile and accessibility | The native mobile app was delisted; Roll20 directs users to mobile-browser characters and compendiums. D&D and Demiplane sheets are described as phone optimized; other systems vary. Touch/tablet VTT improvements, keyboard shortcuts, screen-reader token tooltips, and persistent pin controls are documented. [Mobile guide, March 24, 2026](https://help.roll20.net/hc/en-us/articles/4411213438231-Roll20-Mobile-App-FAQ); [VTT improvements](https://help.roll20.net/hc/en-us/articles/25289127045143-VTT-Quality-of-Life-Feature-Improvements); [Token Features](https://help.roll20.net/hc/en-us/articles/360039674573-Token-Features); [Map Pins](https://help.roll20.net/hc/en-us/articles/36271267343639-Map-Pins) | Neither “Roll20 has no mobile support” nor comprehensive accessibility superiority is justified. Complete phone GMing and assistive-technology workflows remain meaningful tests. |
| Transfer and export | Transmogrifier copies content between games owned by the same user; it is an internal reuse workflow. Roll20 Characters supports character transfers, including a linked single-game mode; copies and snapshots behave differently. New D&D sheets gained Print-to-PDF public beta in June. [Transmogrifier](https://help.roll20.net/hc/en-us/articles/360037774433-Transmogrifier); [Roll20 Characters](https://help.roll20.net/hc/en-us/articles/360037258594-Roll20-Characters); [Print-to-PDF, June 11, 2026](https://blog.roll20.net/posts/public-beta-print-to-pdf/) | Do not claim there is no export. Full portable campaign round-trip is a different promise that needs its own proof. The Transmogrifier help article conflicts with itself about macros; do not rely on its macro limitation without observation. |
| Extensions and automation | Pro/Elite games support a one-click Mod Script library and a custom JavaScript editor. The server runs a campaign sandbox; it has no HTTP requests, external script loading, or browser DOM. Sandbox 1.5 adds functions/object methods and became the default September 2. Ordinary macros support multiple commands, attributes, targeting, prompts, nesting, and buttons. [Mod Scripts, September 2, 2026](https://help.roll20.net/hc/en-us/articles/360037256714-Introduction-to-Mod-Scripts-API); [Sandbox Model, September 2, 2026](https://help.roll20.net/hc/en-us/articles/360037772853-API-Sandbox-Model); [Macros and Token Actions](https://help.roll20.net/hc/articles/360037256794) | A plugin SDK alone is not a mature extension ecosystem. Evaluate installation, permission clarity, debugging, upgrades, and useful integrations. |

## Pricing, rights, trust, and evidence limits

The live [Feature Breakdown](https://help.roll20.net/hc/en-us/articles/360037774633-Feature-Breakdown), dated November 17, 2025, lists Free; Plus **$5.99/month or $59.99/year**; Pro **$10.99/month or $109.99/year**; Elite **$14.99/month or $149.99/year**. Storage is 100 MB, 4 GB, 10 GB, and 50 GB respectively. Plus adds lighting; Pro adds scripts, Transmogrifier, and custom sheets; Elite adds Dungeon Scrawl Pro. Subscriber-created games share many benefits with players. The page advertises 1,200+ systems and unlimited hosted players/games; that is not a claim of equal automation depth in every system. Content sharing is limited by tier and game/player counts. These are listed prices, not a completed checkout or tax-inclusive quote.

Content access is a separate issue from engine capabilities. Roll20's [Marketplace Asset EULA](https://help.roll20.net/hc/en-us/articles/360037254294-Marketplace-Asset-EULA) describes personal-use assets, provider licenses for certain free content, and rights retained by Roll20/providers. A migration feature must not assume every purchased asset can be redistributed. Licensed publisher relationships and community-produced content are external assets; implementing a parser does not reproduce them.

The [Security page](https://help.roll20.net/hc/en-us/articles/360037770813-Security), dated September 4, 2023, describes encrypted transport/backups and campaign access controls. It explicitly distinguishes account/campaign breaches from game-rule cheating and lists some hidden-information bypasses outside its vulnerability definition. This is a documented policy boundary, not evidence that a specific exploit still works today. The [July 2024 incident FAQ](https://help.roll20.net/hc/en-us/articles/24620372778775-Data-Security-Incident-July-3rd-2024-FAQ) records a historical administrative-account compromise and remediation; it does not establish current insecurity. Neither product received an independent penetration test in this research.

The [September 1, 2026 AI contribution policy](https://help.roll20.net/hc/en-us/articles/43164327041943-AI-Policy-for-Community-Mod-Scripts-Character-Sheets) permits AI-assisted technical contributions with human responsibility, constrains creative contributions, and excludes private custom scripts from its scope. This does not establish a first-party autonomous in-game assistant. No such assistant was established by the official product material researched here; that is a bounded research finding, not proof of universal absence.

Performance claims must be matched to workload. Roll20's [April 23 performance report](https://blog.roll20.net/posts/vtt-performance-april2026/) reports major renderer improvements on a named map and machine. Its [August 14 update](https://blog.roll20.net/posts/performance-updates-aug-14-2026/) acknowledges recent sheet/service delays, reports most resolved, and separates shipped changes from planned work. Those are vendor measurements/status reports. They cannot be converted into an OTE speed advantage, and planned improvements should not count as shipped features. This applies to the [August 18 coming-soon shop/item-transfer and sheet improvements](https://blog.roll20.net/posts/new-dd-features-coming-soon/) too.

## Five differentiators worth proving

These are candidate advantages and proposed acceptance evidence, not claims that OTE has already achieved them. They preserve the broad product objective while making important parts falsifiable.

1. **Much faster preparation with real content.** Give unfamiliar GMs the same legally reusable map, NPCs, room notes, and encounter requirements. Time from a clean account to an invited player's correct playable view. Require usable editors, working links, lighting, and discoverable actions without JSON edits or developer help. Compare against Roll20's guided maps, compendium workflow, and Player View; include prepared-module play as a separate benchmark.
2. **Reliable sessions with an explicit secrecy contract.** Run a multi-hour, multi-client encounter on declared network/device conditions. Record action-to-visible-result latency, reconnections, roll duplication, concurrent edits, and lost work. Inspect player HTTP/WebSocket payloads and reconnect history for hidden actor/scene/chat information. Prove recovery and correct permissions, not only smooth local rendering.
3. **Ownership and extensibility people can use.** Export a complete user-owned campaign with assets, references, rules configuration, and reusable content; restore it on a fresh independent instance and resume play. Have an independent developer install, understand, upgrade, and remove a useful external integration through documented permission-checked APIs. Compare the result against Roll20's internal transfers and one-click script library without claiming unsupported content rights.
4. **Complete accessible play across devices.** Have a keyboard/screen-reader user and a phone user create or join characters, inspect a scene, move, target, roll, chat, handle initiative, and recover from navigation mistakes. Include phone GM preparation and live intervention. Require observable completion and retained state; viewport screenshots and automated accessibility scores alone are insufficient.
5. **Useful, trustworthy agent execution.** Test OTE's existing automatic agent on multi-step prep and live-play tasks with a real provider, source-grounded rules answers, visible completed results, permission-denial cases, correction, and recoverable mistakes. Measure successful user outcomes and time saved relative to manual Roll20 workflows. A chat box, a canned response, or an unexecuted proposal is not proof. Preserve the repository's existing agent behavior while gathering evidence.

A credible superiority verdict needs task-level wins, no critical regression in core play, and honest scope for licensed content, community adoption, and production operations. Feature counts, passing tests, or an agent's confidence alone cannot establish that users will prefer the product or that an incumbent will view it as a competitive threat.
